# Юркар Web / PWA

Самостоятельный веб-проект без зависимостей от Gradle и Android. Node.js 20+ используется только для локального сервера, тестов и сборки. В браузере — ES modules, CSS, service worker. Можно вынести всю папку в отдельный репозиторий без Android-файлов.

## Запуск

Из этой папки: `npm run dev`, затем http://127.0.0.1:4173. Проверка: `npm test`. Сборка: `npm run build`, результат — `dist/`.

## Реализовано

Адаптивный интерфейс в оформлении Android, светлая/тёмная тема и основные вкладки Главная / SOS / Карта услуг / Профиль. До 10 автомобилей с паспортом (поколение, двигатель, силовая установка, коробка, режим поездок); история обслуживания и планы с датой/пробегом, выполнение плана; персональные советы; каталог 565 моделей с ручным вводом; редактируемый чек-лист до 30 пунктов; JSON-копии и восстановление. Записи ограничены 200 на тип и автомобиль. Повреждённое хранилище не затирается автоматически.

Из Kotlin-источников экспортированы 79 статей с действиями, возможными причинами, работами и источниками; 56 узлов атласа; 63 индикатора; 15 категорий услуг и 13 компаний; точки карты; 4 городских материала; SOS; 8 документов и 152 изображения. Контент не пересказан моделью. Витрины товаров и штрафов остаются разделами «скоро», как в Android. Юридические тексты перенесены из приложения и требуют согласования применимости к веб-сервису перед полноценным запуском аккаунтов.

Профиль разделён на личный кабинет, настройки приложения и управление локальными данными. Темы: как в системе / светлая / тёмная. Настраивается автопереход сторис; есть пауза, ручное переключение, клавиши-стрелки и отметки просмотра. Таймер приостанавливается в скрытой вкладке. В гараже вкладки Советы / Забота / Сервисы, подбор моделей по выбранной марке. Справочник использует иллюстрированные карточки приложения, фильтры по категориям, зонам и срочности; поиск включает причины и группы работ. На карте есть фильтр типа места. Для нового гаража стартовый чек-лист совпадает с Android; старые веб-списки сохраняются при миграции. Браузерная сессия при тестировании проверена отдельно от данных пользователей на публичном сайте.

Данные сохраняются только в браузере. Авторизации, синхронизации с Android, онлайн-записи, платежей, рекламного кабинета и push-уведомлений пока нет. Карта OpenStreetMap и внешние ссылки требуют сети; материалы, иллюстрации и гараж после загрузки PWA доступны офлайн. Веб-атлас использует карточки зон и деталей, не Android 3D-рендерер. Импорт JSON предназначен для веб-копий, не для прямого чтения Android SharedPreferences. Переход на другой origin (например с github.io на yurcar.ru) не переносит браузерный гараж автоматически: экспортируйте JSON на старом адресе и импортируйте на новом.

## Обновление материалов из Android

Из папки веб-проекта: `./scripts/export-android.ps1 -AndroidRoot 'путь-к-Android-проекту'`. Локальный экспорт использует имеющиеся Kotlin compiler 2.1.20 и Gson из Gradle cache, не запускает Gradle и не изменяет Android. Kotlin-модели вычисляются оригинальным кодом (включая дополнения статей), затем формируется `src/android-content.js`; изображения и документы копируются в assets. Временные файлы `.content-export/` игнорируются. Для обычной веб-сборки Kotlin не нужен — сгенерированный контент хранится в Git. После экспорта выполните `npm test` и `npm run build`. При смене набора офлайн-ресурсов увеличивайте CACHE в sw.js.

## Отдельный репозиторий

Репозиторий: `MyCarDevelopment/yurcar-web`. Предыдущий учебный React/Vite-проект сохранён целиком в `legacy-learning/` при переносе через GitHub, включая исходники и прежние настройки Netlify. Он не включается в сборку PWA. Android-проект публиковать в этот репозиторий не нужно.

В `.github/workflows/pages.yml` настроены тесты, сборка и публикация `dist` при обновлении main. В Settings → Pages выбран Source → GitHub Actions. Для pull request выполняются только проверки. 27.10.2026 обновлённая PWA успешно опубликована; в Pages сохранён Custom domain `yurcar.ru`.

## Публикация и yurcar.ru

Проект переносим между хостингами: загрузите содержимое `dist/` в корень статического сайта. Сборочная команда `npm run build`, каталог публикации `dist`. Сервер должен отдавать `.webmanifest` как `application/manifest+json`, JS как JavaScript, а `sw.js` и `index.html` — с проверкой обновлений (`Cache-Control: no-cache`). HTTPS обязателен для PWA вне localhost. Приложение поддерживает размещение в подпапке и hash-навигацию без SPA rewrite.

REG.RU используется как регистратор и DNS, GitHub Pages — как хостинг PWA. 27.10.2026 для yurcar.ru в REG.RU сохранены DNS-серверы ns1.reg.ru / ns2.reg.ru; четыре A-записи `@` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`; CNAME `www` → `mycardevelopment.github.io.`. Существовавшая TXT/SPF-запись перенесена без изменения. На момент проверки распространение делегирования ещё не завершилось: публичный DNS возвращал старые серверы ns1.hosting.reg.ru / ns2.hosting.reg.ru и адрес 31.31.196.17. GitHub ожидал DNS-проверку, Enforce HTTPS был недоступен. После распространения DNS (может занять до 24 часов) проверить выпуск сертификата и включить Enforce HTTPS. Установка PWA на домене требует HTTPS. Для будущего API можно использовать api.yurcar.ru или прокси /api.

## Общий backend

См. [docs/backend.md](docs/backend.md). Интерфейс репозитория отделён от UI в `src/repository.js`: LocalRepository используется сейчас, ApiRepository — заготовка для будущего сервера. Не переключать адаптер до реализации API и авторизации. Секреты и ключи серверных сервисов нельзя включать в статический frontend.

Для обновления оболочки изменяйте версию CACHE в `sw.js`; новый worker активируется после закрытия старых вкладок. В service worker кэшируются только перечисленные статические ресурсы, не ответы API и не пользовательские JSON-копии.
